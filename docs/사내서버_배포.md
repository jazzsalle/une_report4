# 사내 배포서버 배포 (Vercel → 사내 서버)

회사 「배포서버 서비스 배포 지침」(2026-11-17, `unes-svc` 방식)을 따른다. 이 문서는 **이 서비스에 맞춘 값**과 **Vercel과 달라진 점**만 적는다.
서버 주소·비밀번호·API 키는 여기에 적지 않는다.

## 이 서비스의 값

| 항목 | 값 |
|---|---|
| 서비스 이름 | `disaster-report` |
| 앱 폴더 | `/Volumes/UNES2/apps/disaster-report` (본인 소유, `deploy/unes-server` 브랜치) |
| 시작 파일 | `server.js` — `127.0.0.1` + `unes-svc`가 배정한 `PORT`에서만 대기 |
| DB / DB 사용자 | `disaster_report` (`unes-svc db create`로 생성, 본인 계정으로 접속하면 앱 사용자로 자동 전환) |
| 설정 파일 | `/usr/local/etc/unes-svc/env/disaster-report.env` |
| 로그·상태 | `sudo /usr/local/sbin/unes-svc logs disaster-report 200` / `status disaster-report` |

## Vercel과 달라진 점

- **DB 드라이버**: `DATABASE_URL`이 Neon 주소(`*.neon.tech`)면 Neon HTTP, 그 밖의 Postgres는 일반 연결(`pg` 연결 풀). `DB_DRIVER=neon|pg`로 강제 가능. — `src/lib/db/index.ts`, `scripts/seed.ts`, `scripts/migrate.ts`
- **시작**: `server.js`가 작업 폴더를 자기 위치로 옮기고 `.env`가 있으면 읽은 뒤 `127.0.0.1`에서만 대기한다.
- **휴지통 정리**: 지침상 예약 작업(cron)을 쓸 수 없어서, `vercel.json`의 crons 대신 `server.js`가 매일 03:00(한국시각) `/api/cron/purge-trash`를 부른다. 시각은 `PURGE_AT_KST=HH:MM`으로 바꿀 수 있다. 로그에 「휴지통 정리 200 …」으로 남는다.

## 설정 파일 항목

| 변수 | 값 |
|---|---|
| `DATABASE_URL` | `unes-svc db create`가 자동으로 넣음 (Neon 주소를 넣지 않는다) |
| `SESSION_SECRET` | 서버에서 새로 생성 (`openssl rand -hex 32`) |
| `CRON_SECRET` | 서버에서 새로 생성 (`openssl rand -hex 16`) |
| `TZ` | `UTC` (Vercel과 같게. 화면의 한국시각 표시는 코드가 맞춘다) |
| `KMA_SERVICE_KEY` | Vercel 값 그대로 |
| `T3Q_SOP_MODE`, `T3Q_SOP_URL`, `T3Q_SOP_CERT_SHA256` | Vercel 값 그대로. 인증서 지문은 T3Q 인증서가 바뀌면(약 90일 주기, 2026-11 갱신 → 2027-02-13 만료) 새 값으로 교체 — `check-links.mjs`가 새 지문을 보여 준다 |
| `PORT`, `HOST` | `unes-svc`가 자동으로 넣음 (적지 않는다) |

수정 후에는 `sudo /usr/local/sbin/unes-svc restart disaster-report`.

## 처음 배포 순서

```bash
sudo /usr/local/sbin/unes-svc create disaster-report
cd /Volumes/UNES2/apps/disaster-report
git clone -b deploy/unes-server https://github.com/jazzsalle/une_report4.git .
sudo /usr/local/sbin/unes-svc db create disaster-report
eval "$(/opt/homebrew/bin/brew shellenv)"
npm ci && npm run build
# 설정 파일에 위 항목 추가 후
sudo /usr/local/sbin/unes-svc daemon disaster-report server.js
sudo /usr/local/sbin/unes-svc status disaster-report
# 개발팀장이 DNS 등록을 마친 뒤
sudo /usr/local/sbin/unes-svc domain disaster-report <서브도메인 앞부분>
```

## 데이터 옮기기 (Neon → 사내 PostgreSQL)

Neon은 PostgreSQL 18이고 서버의 `pg_dump`는 17이라 덤프가 안 된다(버전 불일치). 대신 표 단위로 직접 복사한다.

```bash
cd /Volumes/UNES2/apps/disaster-report
eval "$(/opt/homebrew/bin/brew shellenv)"
node scripts/copy-from-neon.mjs "postgresql://<사용자>@<Neon 직접 연결 주소>/<DB>?sslmode=verify-full"
```
- `Neon 비밀번호:`가 나오면 비밀번호를 붙여 넣는다(화면에 안 보임). 주소에는 비밀번호를 넣지 않는다.
- Neon 주소는 Vercel의 `DATABASE_URL_UNPOOLED`(호스트에 `-pooler`가 없는 것).
- 서버 DB 스키마를 먼저 최신으로 만들고, 양쪽에 있는 표·열만 글자 그대로 옮긴 뒤 표마다 건수를 비교해 보여 준다.
- 서버 DB에 이미 데이터가 있으면 멈춘다. 최종 이전 때 다시 옮기려면 `--replace`(서버 DB 내용을 지우고 다시 옮김).
- 옮기는 동안 Vercel 쪽에 새로 입력된 내용은 넘어오지 않으므로, 최종 이전 직전부터 Vercel 주소 사용을 멈춘다.

## 업데이트(새 코드 반영)

```bash
cd /Volumes/UNES2/apps/disaster-report
eval "$(/opt/homebrew/bin/brew shellenv)"
git pull
npm ci
DATABASE_URL="postgresql:///disaster_report?host=/tmp" npm run db:migrate
npm run build
sudo /usr/local/sbin/unes-svc restart disaster-report
```

## 참고

- 점검: `node scripts/check-links.mjs` — 설정 파일 항목과 기상청·T3Q 연결을 앱과 같은 방식으로 확인한다(키·주소는 화면에 안 나옴). T3Q 인증서 만료가 30일 안이면 알려 준다.
- 사내망에서는 공인 도메인으로 접속되지 않는다(지침). 회사 안에서 화면을 볼 때는 SSH 터널: `ssh -L <포트>:127.0.0.1:<포트> <계정>@<서버>` 후 브라우저에서 `http://127.0.0.1:<포트>`.
- 현장 응답 링크는 접속한 주소(`window.location.origin`)로 만들어지므로 새 도메인으로 자동으로 바뀐다. 이전 Vercel 주소로 이미 보낸 링크는 Vercel을 끄면 열리지 않는다.
- T3Q 링크 로그인(`/sso/t3q`)을 쓰게 되면 T3Q에 새 도메인을 알려야 한다.
- 이전이 끝나고 Vercel을 정리할 때 Neon DB도 삭제하거나 비밀번호를 바꾼다.
