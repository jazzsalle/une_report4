# 사내 배포서버 배포 (Vercel → 사내 서버)

회사 「배포서버 서비스 배포 지침」을 그대로 따른다. 이 문서는 **이 서비스에 맞춘 값**과 **Vercel과 달라진 점**만 적는다.
서버 주소·비밀번호·API 키는 여기에 적지 않는다(지침 2-7).

## 이 서비스의 값

| 항목 | 값 |
|---|---|
| 서비스 폴더 | `/Volumes/UNES2/apps/disaster-report` |
| 시작 파일 | `server.js` — `127.0.0.1:PORT`(기본 4200)에서만 대기 |
| 시작 래퍼 | `/usr/local/libexec/unes-disaster-report-start` |
| 데몬 | `/Library/LaunchDaemons/kr.unes.disaster-report.plist` (UserName=deploy) |
| 로그 | `/Library/Logs/unes/kr.unes.disaster-report.log` |
| DB / DB 사용자 | `disaster_report` / `disaster_report` (서버의 PostgreSQL 17, `127.0.0.1:5432`) |
| 설정 파일 | 서비스 폴더의 `.env` (Git 제외) |

## Vercel과 달라진 점

- **DB 드라이버**: `DATABASE_URL`이 Neon 주소(`*.neon.tech`)면 Neon HTTP, 그 밖의 Postgres는 일반 연결(`pg` 연결 풀). `DB_DRIVER=neon|pg`로 강제 가능. — `src/lib/db/index.ts`, `scripts/seed.ts`, `scripts/migrate.ts`
- **시작**: `server.js`가 작업 폴더를 자기 위치로 옮기고(래퍼에서는 `cd` 금지) `.env`를 읽은 뒤 `127.0.0.1`에서만 대기한다.
- **휴지통 정리 크론**: `vercel.json`의 crons 대신 `server.js`가 매일 03:00(한국시각) `/api/cron/purge-trash`를 부른다. 시각은 `PURGE_AT_KST=HH:MM`으로 바꿀 수 있다. 결과는 로그에 「휴지통 정리 200 …」으로 남는다.
- **스키마 변경 반영**: `npm run db:migrate` (마이그레이션만, 계정은 만들지 않음). `npm run db:seed`는 빈 DB를 처음 만들 때만 쓴다.
- **시간대**: Vercel과 같게 데몬 환경변수에 `TZ=UTC`를 둔다(화면의 한국시각 표시는 코드가 따로 맞춘다).

## .env 항목

| 변수 | 값 |
|---|---|
| `DATABASE_URL` | `postgresql://disaster_report:<DB 비밀번호>@127.0.0.1:5432/disaster_report` (비밀번호는 영문·숫자만) |
| `SESSION_SECRET` | Vercel 값 그대로 (바꾸면 모든 사용자가 다시 로그인) |
| `CRON_SECRET` | Vercel 값 그대로 |
| `KMA_SERVICE_KEY` | Vercel 값 그대로 |
| `T3Q_SOP_MODE`, `T3Q_SOP_URL`, `T3Q_SOP_CERT_SHA256` | Vercel 값 그대로. 인증서 지문은 T3Q 인증서가 바뀌면(현재 2026-12-15 만료) 새 값으로 교체. T3Q 루트 인증서를 받으면 `T3Q_SOP_CA`로 전환 |
| `T3Q_MODE`, `T3Q_BASE_URL`, `T3Q_TOKEN` | Vercel에 있으면 그대로 |
| `DEMO_LOGIN` | 정식 운영에서는 넣지 않음 |

## 데이터 옮기기 (Neon → 사내 PostgreSQL)

1. Neon 연결 주소는 Vercel 프로젝트 → Settings → Environment Variables의 `DATABASE_URL_UNPOOLED`(없으면 `DATABASE_URL`).
2. 덤프: `pg_dump "<Neon 주소>" -Fc --no-owner --no-privileges -f .backup/neon-<날짜>.dump`
3. 복원: `pg_restore --no-owner --no-privileges -d "postgresql://disaster_report@127.0.0.1:5432/disaster_report" -W .backup/neon-<날짜>.dump` — 반드시 `disaster_report` 사용자로 접속해 표의 주인이 앱 사용자가 되게 한다.
4. 옮기는 동안 Vercel 쪽에 새로 입력된 내용은 넘어오지 않으므로, 덤프 직전부터 Vercel 주소 사용을 멈춘다.

## 업데이트(새 코드 반영)

```bash
cd /Volumes/UNES2/apps/disaster-report
git pull
npm ci
npm run db:migrate
npm run build
```
그 뒤 `sudo launchctl kickstart -k system/kr.unes.disaster-report`.

## 참고

- 사내망에서는 공인 도메인으로 접속되지 않는다(지침 4-7). 확인은 휴대폰 LTE 등 외부망에서 한다.
- 현장 응답 링크는 접속한 주소(`window.location.origin`)로 만들어지므로 새 도메인으로 자동으로 바뀐다. 이전 Vercel 주소로 이미 보낸 링크는 Vercel을 끄면 열리지 않는다.
- T3Q 링크 로그인(`/sso/t3q`)을 쓰게 되면 T3Q에 새 도메인을 알려야 한다.
