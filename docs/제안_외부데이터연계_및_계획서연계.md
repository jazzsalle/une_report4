## ① 외부 재난정보 API 연계

### 원칙
1. **상황일지에 바로 '사실'로 쓰지 않는다.** 외부 데이터는 수행 이력에 **「확인 필요」 후보**로 들어오고, 담당자가 확인한 것만 상황일지에 반영한다. (요구사항 UFR-007-001 확인 상태와 동일)
2. 모든 값은 **출처·조회시각**과 함께 저장한다. (기상특보와 같은 방식)
3. 연계 코드는 T3Q와 같은 **어댑터 구조**로 둔다: `src/lib/external/<출처>.ts` → 공통 형식 `{ kind, title, body, source, observedAt }`.
4. 상황이 **진행 중일 때만** 10분 단위로 조회한다. 평상시에는 호출하지 않는다.

### 단계별 추진 (권장)

| 단계 | 대상 | 이유 |
|---|---|---|
| 1단계 (즉시) | 부산 강우량·하천수위, 긴급재난문자 | 기존 data.go.kr 인증키로 활용신청만 하면 됨. 상황일지 「기상 현황」「상황 전파」가 바로 채워져 체감 효과가 큼 |
| 2단계 | 인명피해 우려지역, 대피소 | 파일 데이터 → DB 적재 1회. SOP 세부항목·대피 기록 입력을 편하게 함 |
| 3단계 | 홍수통제소, 산림청, 경찰청 돌발 | 별도 키 발급·기관 협의 필요 |
| 협의 | 부산시 미공개 데이터 (도로침수 35개소, 침수위험지도 원본) | 부산시 자연재난과에 직접 요청 |

### NDMS 입력과의 관계
공무원이 가장 원하는 것은 NDMS에 옮겨 적을 내용이 이미 정리되어 있는 것입니다. 1·2단계만 연계해도 「기상 현황」「피해 현황(대피·통제)」「상황 전파」 표가 자동으로 채워지므로, 사용자가 직접 넣는 것은 **피해 수치와 응급복구 내용** 정도로 줄어듭니다.

## ② 계획서 생성도구 ↔ 상황일지 생성도구 연계

### 역할 구분
| 구분 | 계획서 생성도구 | 상황일지 생성도구 |
|---|---|---|
| 재난관리 단계 | 예방 · 대비 | 대응 · 복구 |
| 성격 | **미리 정한 것** (조직, 자원, 연락체계, 단계별 조치) | **실제로 한 것** (SOP 실행, 전파, 피해·복구) |

### 연계점: 「사전계획 대비 대응 결과」
상황일지 목차에 장 하나를 추가합니다.

> **8. 사전계획 대비 대응 결과**
>
> | 계획 항목 | 계획 내용 | 실제 수행 | 비고 |
> |---|---|---|---|
> | 비상근무 편성 | 2단계 시 20명 | 18명 응소 (19:10) | 미응소 2 |
> | 양수기 확보 | 30대 | 12대 투입 | 이행 |
> | 취약지역 예찰 | 인명피해 우려지역 25개소 | 25개소 완료 | 이행 |

- 사후 평가·개선 보고, 다음 해 계획 수립의 근거가 됩니다.
- 복구 완료 후에는 이 표의 「비고」를 계획서 생성도구의 「향후 개선사항」으로 되돌려 보내 **계획 → 대응 → 개선 → 계획** 순환을 만듭니다.

### 동작 방식 (단순하게)
1. 상황·기상 탭에 **「사전계획 불러오기」** 카드 1개 — 계획서 생성도구에서 만든 hwpx/docx 파일을 올림
2. 시스템이 목차별로 본문을 추출 (hwpx `section0.xml` / docx 문단)
3. 추출한 「조직 편성」「자원」「비상연락」「단계별 조치」를
   - SOP 생성 시 T3Q 요청의 참고 문서로 함께 전달 → **계획서 기반 SOP**
   - 상황일지 8장 표의 「계획 내용」 열에 자동 기입
4. 상황일지 개요에 「근거 계획: ○○○ 계획서(2026.3.3.)」 한 줄 표기

### 두 도구가 함께 정할 것 (공통 규격)
안정적으로 읽으려면 파일 속에 **공통 메타정보**를 넣어 두는 것이 가장 확실합니다.

| 항목 | 위치 | 예 |
|---|---|---|
| 문서종류 | hwpx `content.hpf` 메타 / docx 사용자 속성 | `docType=계획서` |
| 재난유형·지역·기간 | 동일 | `hazard=호우; region=부산광역시` |
| 공통 목차 코드 | 목차 제목 앞 숨은 코드 또는 메타 목록 | `ORG` 조직편성, `RES` 자원, `CONTACT` 비상연락, `ACT` 단계별 조치 |

공통 목차 코드만 합의하면, 계획서 목차 이름이 바뀌어도 상황일지가 올바른 내용을 찾아올 수 있습니다.

### 화면 톤
계획서 생성도구와 같은 KRDS 토큰·헤더 구조(유틸리티 바 + GNB)·라벨 행 입력폼·하단 우측 주요 버튼 배치를 이미 적용했습니다. 두 도구를 하나의 포털 메뉴로 묶을 경우 상단 유틸리티 바의 도구명만 바꾸면 됩니다.
