API 요청서로

이 문서는

매뉴얼의 어느 칸을 API의 어느 필드로 뽑는지 매뉴얼 캡처로 보여 주고, 그 필드가 API로 들어오면 우리 화면에 어떻게 나오는지 보여 줍니다.

캡처는 부산광역시 풍수해 현장조치 행동매뉴얼 예시이며, 다른 재난유형·지자체 매뉴얼도 같은 계층과 규칙으로 추출합니다.

매뉴얼은 재난대응 프로세스 표(목차 역할 — 단계·임무·조치·세부행동)와 행동카드(조치 1건의 기관·표준행동·전파·자원)로 되어 있습니다. 두 곳은 코드번호(예: 1-1)로 연결되며, JSON에서는 actionCode가 그 연결 고리입니다.

고르는 순서

순서규칙
1재난유형이 같은 매뉴얼만
2발생 시군구 매뉴얼(예: 영천시) → 없으면 시도 매뉴얼(경상북도) → 없으면 중앙부처 매뉴얼. 시군구가 여럿이면 시도
3같은 기관 매뉴얼이 여러 판이면 최신판
4고른 매뉴얼에서 responseStep의 조치만. 위기경보로 단계를 나눈 매뉴얼이면 alertLevel로
5그중 department의 행만. 매뉴얼에 없는 부서면 초기대응(총괄) 행을 주고 departmentMatched: false → 화면에 「요청 부서 없음 — 초기대응부서 기준」

고른 매뉴얼은 응답 manual로 돌려받아 SOP 화면에 「○○ 기준」으로 표시합니다(⑤). 맞는 매뉴얼이 없으면 NO_DOCUMENT.

②행동카드 → 조치 상세

프로세스 표의 조치 1건마다 행동카드 1장이 있습니다. 카드 코드번호로 프로세스의 [n-m]과 짝을 맞춥니다. (매뉴얼 41쪽, 1-1)

번호매뉴얼JSON 필드
1카드 단계 표시 「징후 감지」responseStep 확인용 (프로세스 표와 같아야 함)
2코드번호 1-1actionCode — 프로세스 [1-1]과 연결
3조치목록actionName (프로세스 표 제목이 있으면 그것을 우선)
4조치내용summary
5주관부서organizations[] role: LEAD
6지원부서organizations[] role: SUPPORT (쉼표마다 1건)
7협업기관organizations[] role: COOPERATE
8표준행동 열detailTasks[].title — 프로세스 표에 - 줄이 없을 때만 사용 (규칙 R9)
9세부내용 열detailTasks[].content (같은 표준행동의 여러 줄은 줄바꿈으로 합침)
10비고 열detailTasks[].note

③전파 표 → 전파대상

전파가 있는 카드에는 구분·전파방법·전파대상 표가 붙습니다. 실제 수신자는 화면에서 사용자가 연락망으로 고르고, 이 값은 추천 참고로 씁니다. (매뉴얼 44쪽, 2-2)

번호매뉴얼JSON 필드
1조치목록actionName — 전파 조치임을 알 수 있는 제목
2전파방법propagation[].method (구분과 함께 원문)
3전파대상propagation[].target, 성격에 따라 targetType (기관 ORG · 직위 ROLE · 시민 PUBLIC)
4구분 (UMS, One-Click …)propagation[].channelHint 가까운 값 — UMS·문자 → SMS, 방송·전광판 → BROADCAST, 유선 → PHONE
—표준문안 (카드 아래 「표준문안」 칸)propagation[].messageTemplate — 원문 그대로. 매뉴얼에 문안이 없으면 비움(새로 만들지 않음)

전파 표의 한 행 = propagation[] 1건입니다. 표 아래 * 설명줄(예: 긴급재난문자는 행정안전부 발송)은 조치의 notes[]로 넣습니다.

번호매뉴얼JSON 필드

추출 규칙 R1~R25

같은 매뉴얼이면 누가 뽑아도 같은 JSON이 나오도록 정한 규칙입니다.

규칙매뉴얼 표기JSON 처리예
R1[n] 제목missions[] 1건 (missionCode = n)[3] 기상특보 대응
R2[n-m] 제목actions[] 1건, 소속 임무 = n[3-1] (초기)상황판단회의 개최
R3- 내용바로 위 조치의 detailTasks[]- 비상근무 실시
R4※ 내용바로 위 조치의 notes[] (※ 기호 빼고)※ 재대본 구성 전 재난안전상황실에서 보고
R5기호 없이 이어지는 줄칸이 좁아 줄바꿈된 것 — 앞 줄에 이어 붙임「…영상회의」 + 「(자연재난과장)」
R6코드 여러 개가 한 줄 [3-3][3-4]조치 1건, actionCode = "3-3,3-4", 카드 두 장의 내용을 합침비상연락체계 확인

R8조치 전체에 붙은 (필요시), (피해발생시), ＊○○시제목에서 떼어 condition에 원문 그대로 → 화면은 「필요시 임무」피해조사단 교육 · condition「태풍 한반도 북상 우려시」, 영천 [①-2-3] (필요시) 위험구역의 설정
R9- 줄이 하나도 없는 조치행동카드 표준행동을 detailTasks로 채움[4-1] 기상특보 접수
다른 매뉴얼 모양 (R10~R17)
R10원문자 코드 ①-1-1, 오타 [12-1]숫자로 바꿈 1-1-1. 깊이: ① 협업기능 → ①-1 임무 → ①-1-1 조치영천 [①-2-1] 위기경보 발령
R11같은 코드가 여러 단계에 나옴단계마다 따로 1건. 같은 코드라도 단계별 내용·기관이 다르므로 합치지 않음. 응답에는 요청한 responseStep의 것만영천 ①-2-1이 1·2·3단계에 각각
R12「○○단계 참고」 한 줄뿐인 조치참고한 단계의 같은 코드에서 detailTasks를 가져오고 notes에 「관심단계 참고」를 남김기후부 경계 ①-2-2
R13세부행동 기호가 문서마다 다름조치 바로 아래 첫 깊이 기호 = detailTasks[].title, 그 아래 기호 = content. 기호 순서는 문서마다 정함부산 - · 영천 1.→○ · 기후부 □→○ · 선박 ㅇ
R14표가 쪽을 넘어가며 코드 없이 시작하는 조각새 조치를 만들지 않고 앞 쪽의 마지막 조치에 이어 붙임. 임무도 앞 쪽 것을 이어받음 (R7 적용 안 함)기후부 p.67, 영천 31쪽 [⑨-2-2]
R15하위 항목이 모두 「시기 / 발령권자 / 전파기관:」 같은 속성각각을 조치로 만들지 않고 부모 1건으로. 전파기관·보고대상 → propagation, 참석대상·협조기관 → organizations선박 (마) 위기경보 발령
R16중앙부처·공사 등 기관 매뉴얼지자체가 실행하는 조치만 뽑음 — 「지방자치단체」「산림청·지자체」 행·열. 없으면 actions: []기후부·환경부·항만공사
R17실명·전화번호보내지 않음. 기관·직위만 (organizations, propagation.target)영천 34쪽 담당자 실명
조건 처리 (R18~R19)
R18제목 일부에만 붙은 조건제목 그대로 두고 condition은 비움 — 조치 자체는 꼭 할 일이라 흐름선에 둠영천 ⑪-2-2 교통통제 및 (필요시) 교통통제소 운영
R19프로세스 표의 부서 칸 (초기대응부서 / 협업부서 / 유관기관)요청 department가 든 행 묶음만. 협업기능형은 주관부서가 그 부서인 조치만. 띄어쓰기 무시, 「시민안전실 자연재난과」처럼 상위 조직이 붙어도 같은 부서. 없으면 초기대응 행 + departmentMatched: false부산 p.34 「재난상황실 자연재난과」 행, p.35 「복지정책과」 행 → [3-11] 이재민 임시주거시설
공통 규칙과 예외 원칙 (R20~R25)
R20(공통 전처리) 세로쓰기·줄바꿈으로 끊긴 글자, 띄어쓰기 빠진 PDF, 가운뎃점 6종(· ․ ‧ ㆍ ･ ・), 쪽 머리글·쪽번호이어 붙이고 띄어쓰기 무시로 비교, 가운뎃점 통일, 머리글 지움. 같은 문서 중복은 하나만, 한 파일에 매뉴얼이 여럿이면 나눔
R21코드 오타·반복 ([45--2], [[7], 목차·개요·사례에 같은 [n-m] 반복), 번호 없는 [징후접수 및 파악]오타 바로잡기. 반복 코드는 「주관부서」 등 카드 머리가 뒤따르는 첫 등장만 조치. 번호 없는 대괄호 소제목도 임무(R7 확장)
R22단계 표기가 프로세스 표와 카드에 다름, 비표준 단계명(「비상저감 1~3단계」), 「(계속)」·●○ 표행동카드 머리의 단계 표기가 우선. 비표준 단계명은 열 위치로 4단계에. 「(계속)」·○는 앞 조치가 이어지는 것(새 조치 아님)
R23[필요시]만 있는 줄, 카드 안 ①②③ 조건 목록그 아래 항목들의 condition. 조건 목록의 원문자는 협업기능 번호(R10)가 아님
R24실무·표준·기관 매뉴얼의 경보단계별 「기관별 임무·역할」 표, 3열 조치목록(조치사항/세부내용/비고)지자체 별칭 행만 조치로(지자체·지방자치단체(소방관서 포함)·시도 및 시군구·지자체(지대본)·비고 「(지자체)」), 단계 = 경보단계. (가)=임무, (가-1)=조치. 오인 제외: 위기유형별 주관기관 표, 시·도교육청, 시·도 119, 부처 내부 대응 프로세스·협업기능 표, 「주요 조치내용(주관기관)」
R25예외 원칙 — 위 규칙으로 정할 수 없는 곳만들지 않습니다. 원문을 그대로 두고 warnings[]에 이유·쪽(지자체 조치 없음, 단계·코드 판단 불가, 그림 쪽, 표 짝 안 맞음). 문서 하나에 맞춘 규칙은 추가하지 않고, 여러 문서 유형에 반복될 때만 규칙을 늘립니다

애매한 경우

제목만 있고 내용이 없을 때

프로세스 표에도 행동카드에도 세부 내용이 없으면 detailTasks: []로 둡니다. 매뉴얼에 없는 내용은 만들지 않습니다. 화면에서 담당자가 직접 채웁니다.

프로세스와 카드 내용이 다를 때

제목·순서·세부행동은 프로세스 표, 기관·전파·자원은 행동카드를 따릅니다. 카드 코드가 프로세스에 없으면 해당 단계 끝에 붙이고 sources에 쪽을 남깁니다.

한 조치가 여러 단계에 나올 때

단계마다 따로 1건씩 만듭니다. actionCode는 매뉴얼 코드 그대로이고, 응답은 요청한 responseStep의 것만 보냅니다.

조건이 세부행동에 붙어 있을 때

- (필요시) 비상근무 실시처럼 세부행동 앞의 조건은 떼지 않고 detailTasks[].title에 그대로 둡니다. condition은 조치 제목에 붙은 조건만 씁니다.
