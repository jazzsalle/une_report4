SOP 추출 표준 — 재난 매뉴얼에서 상황별 SOP 뽑기

사내 · v1 · 2026-10-20

이 문서

재난 매뉴얼에서 상황(재난유형·지역·단계·부서)에 맞는 SOP — 임무·조치·세부행동·기관·전파·자원 — 를 뽑는 기능의 사내 표준입니다. 특정 공급자에 기대지 않고, 우리 SW에 직접 탑재하거나 API 서비스로 제공할 때 이 문서대로 만들면 받는 쪽(화면·보고서)을 바꾸지 않고 쓸 수 있습니다. 재난상황일지 생성도구(report4)를 만들며 약 80개 매뉴얼로 정리한 규칙과 운영하며 정한 판단을 담았습니다.

만드는 쪽 (추출기)③ 매뉴얼 데이터 → ⑤ 매뉴얼 선택 → ⑥ 추출 원칙 → ④ 계약 → ⑧ 검증
쓰는 쪽 (화면·보고서)④ 계약 → ⑦ 받는 쪽 처리 규칙
상황정보→매뉴얼 1종 선택→단계 선택→부서 행 선택→조치 추출→응답→받는 쪽 검증·변환
② 매뉴얼 체계③ 매뉴얼 데이터④ 계약⑤ 매뉴얼 선택⑥ 추출 원칙⑦ 받는 쪽 처리⑧ 검증⑨ 참고 구현

②매뉴얼 체계 — 무엇으로 SOP를 만드나

재난 매뉴얼은 세 단계입니다. SOP 품질은 어떤 매뉴얼을 쓰느냐로 대부분 정해집니다.

종류 (kind)만드는 곳내용지자체 SOP로
현장조치 행동매뉴얼 ACTION시군구 · 시도 · 시도 교육청 (공공기관도 자체판 보유)그 기관이 실제로 할 조치 — 프로세스 표, 행동카드(주관·지원·세부행동·전파·자원)가장 적합
위기관리 표준매뉴얼 STANDARD재난관리 주관부처 (관계부처 합동 등)정부 전체 역할 분담 — 위기경보 단계별 「기관별 임무·역할」 표. 지자체 칸은 한 줄짜리 공통 역할지역 매뉴얼이 없을 때만 (공통 역할 수준)
위기대응 실무매뉴얼 PRACTICE각 부처·기관그 부처 직원이 할 대응 절차쓰지 않음 (다른 기관의 절차라 틀린 SOP가 됨)

도(道) 담당자처럼 여러 시군에 걸친 상황을 다루는데 도 자체 행동매뉴얼이 없는 경우, 표준매뉴얼의 지자체 칸(상황 총괄·전파·대책본부 가동 등)이 방향이 맞습니다. 시군 행동매뉴얼을 대신 쓰면 다른 기관의 현장 조치가 됩니다.

③매뉴얼 데이터 준비

선택 규칙(⑤)이 동작하려면 매뉴얼마다 아래 메타데이터가 있어야 합니다. 본문은 PDF 원본을 보관해 쪽 이동이 되게 합니다.

운영 원칙

  • 같은 기관·같은 종류는 최신판만 사용(옛판은 보관). 연·월은 파일 이름이 아니라 표지로 확인 — 파일 이름과 실제 판이 다른 경우가 많음.
  • 파일 이름 규칙(검색용): 재난유형_{1표준|2실무|3행동}매뉴얼_발행기관(YYYY.MM).확장자 — 예: 지진_3행동매뉴얼_경북의성군(2019).pdf
  • 비상연락망의 실명·휴대전화는 SOP에 싣지 않음(⑥ R17). 연락처는 기관 연락망에서 따로 관리.
  • 매뉴얼 원본은 공개 저장소에 올리지 않음.

④계약 — 요청 · 응답 · 오류

한 번 호출로 매뉴얼 1종의 SOP 전체를 돌려줍니다(받는 쪽은 다시 부르지 않고 흐름도·상세·전파를 모두 구성). 라이브러리 함수든 HTTP API든 입출력 모양은 같게 합니다.

⑤매뉴얼 선택 규칙

응답은 언제나 매뉴얼 1종의 조치만 담습니다(여러 매뉴얼을 섞으면 단계·코드·기관이 어긋남).

순서규칙이유
1disasterType이 같은 매뉴얼만
2발생 시군구가 1곳이면 그 시군구 행동매뉴얼현장 조치가 가장 구체적
3없거나 시군구가 여럿이면 그 시도 행동매뉴얼여러 시군에 걸치면 시도가 총괄
4학교시설은 시군구를 보지 않고 시도 교육청 행동매뉴얼학교는 교육청 관할
5지역 매뉴얼이 없으면 중앙 표준매뉴얼(kind: STANDARD)의 지자체 칸지자체 공통 역할은 맞음
6실무매뉴얼(PRACTICE)은 지자체 요청에 고르지 않음 → 표준도 없으면 404다른 기관의 절차
7공공기관 자체 매뉴얼(AGENCY: 공항·항만공사·발전사 등)은 지역 요청에 고르지 않음그 기관 시설 전용
8같은 기관·같은 종류 여러 판이면 최신판
9단계: stepBasis=RESPONSE_STEP이면 responseStep, ALERT_LEVEL이면 alertLevel(없으면 대응단계를 경보로 환산: 징후감지→관심 …)
10부서: department가 든 부서 칸의 조치만. 없으면 초기대응(총괄) 칸 + departmentMatched: false. 표준매뉴얼은 지자체 칸R19

(선택 기능) responsibleRegion이 기관명이면 그 기관의 매뉴얼을 먼저 고릅니다 — 중앙부처·공공기관 사용자용. 이때는 그 기관의 실무·행동매뉴얼이 맞는 매뉴얼입니다.

⑥추출 원칙

매뉴얼의 어느 칸이 어느 필드가 되는지는 상세 규칙 R1~R25(캡처 포함)에 있습니다 — 추출 규칙 상세(외부 공급자에게 준 설명서이지만 규칙은 이 표준과 같음). 구현 시 반드시 지킬 핵심:

원칙내용
계층재난대응 프로세스 표 [n] = 임무, [n-m] = 조치, 그 아래 줄 = 세부행동. 기관·전파·자원은 행동카드에서
원문 그대로조치명·단계명·조건·표준문안은 원문 그대로. 새로 짓거나 요약하지 않음. 표준문안이 없으면 비움
코드원문 코드 유지(「3-3,3-4」처럼 한 줄 두 코드는 조치 1건). 코드가 없으면 {단계}-{순번}, 같은 판이면 늘 같은 코드
조건 (R8·R18·R23)조치 전체에 붙은 「필요시 · ○○시」만 condition. 제목 일부의 조건은 아님
표준매뉴얼 (R24)위기경보 단계별 「기관별 임무·역할」 표의 지자체 칸(「지자체」「지방자치단체」「시·도 및 시·군·구」) 항목을 조치로. 칸 이름을 주관(LEAD)으로. 칸 안 소제목(【초기대응 활동】 등)은 임무로 나눔. 같은 문서의 다른 재난 장(예: 풍수해 표준의 대설)은 섞지 않음
개인정보 (R17)실명·전화번호 싣지 않음. 기관·직위만
근거조치마다 docId · page(표기 쪽) · pdfIndex(PDF 0부터)
예외 원칙 (R25)규칙으로 정할 수 없는 곳은 만들지 않고 warnings에 이유·쪽. 추측해서 채우지 않음

⑦받는 쪽 처리 규칙

응답을 화면 SOP로 바꿀 때의 규칙입니다(report4 적용). 추출기가 표준을 덜 지켜도 사용자에게 틀린 SOP가 가지 않게 받는 쪽에서 한 번 더 거릅니다.

매뉴얼 종류별

응답 매뉴얼처리
지역·교육청 행동매뉴얼 (SIGUNGU · SIDO · OTHER)SOP 생성
중앙 표준매뉴얼 (kind: STANDARD, 없으면 제목의 「표준매뉴얼」로 판단)SOP 생성 + 「지역 매뉴얼 없음 — 중앙 표준매뉴얼의 지자체 공통 역할만」 표시
그 밖의 중앙 매뉴얼 (실무 등)만들지 않음 — 「○○의 △△ 행동매뉴얼이 없습니다. 지역 매뉴얼이 등록되면 만들 수 있습니다」

⑧검증 기준

구현이 바뀌어도 아래가 통과해야 합니다. 1~2는 부산광역시 풍수해 현장조치 행동매뉴얼(2026.7.) 원문·대응설명서와 대조한 결과입니다.
